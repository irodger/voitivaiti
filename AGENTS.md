# QA rules

- Codex runs mandatory available checks itself. Do not spend OpenCode quota on routine tests, lint, or builds.
- Before reporting an implementation complete, inspect package.json and the current diff, run `npm test`, run `npm run lint` if that script exists, run `npm run build`, then run `npm run test:e2e:run` against that fresh build. Report absent checks explicitly; do not invent a lint command or install tooling to replace it.
- Reuse a trustworthy successful full E2E result when no subsequent changes affect application behavior, test behavior, dependencies, build configuration, or browser environment. Documentation and whitespace-only edits do not require repeating full E2E. Cite the original log, exit code, coverage, and reason for reuse; label it `PASS (reused)`, never as a new run. If provenance or relevance is uncertain, rerun. User instructions about check scope take precedence.
- After changes to browser tests or their environment, first run one real browser scenario: `node --test --test-concurrency=1 --test-name-pattern="^frontend: onboarding" e2e/professions.e2e.mjs`. Then run the complete E2E suite without E2E_ROLES or a name filter. A filtered run does not replace the full suite.
- This Windows Codex restricted environment blocks Chromium child processes with ACCESS_DENIED (0xC0000022). Run browser checks through the approved execution mechanism outside that restriction. Do not work around it by disabling Chromium's sandbox, changing game behavior, raising timeouts, or weakening assertions. If permission is unavailable, report E2E as BLOCKED.
- Save command output, exit codes, and browser artifacts under `e2e-artifacts/`. The suite records preparation stages and per-scenario traces with screenshots; failures also save screenshots and error details where a page exists. Do not claim UI coverage when Chromium or setup fails.
- Compare `git status --short` before and after QA. Distinguish source changes from ignored build/test artifacts.
- Run OpenCode independent QA by default after a completed batch of substantial functional changes or refactoring, following Codex checks; no separate user request is needed. Substantial means changed user flows, persistence/domain behavior, browser interactions, or shared modules used across components/domains. Run once per meaningful batch, not after every edit. Documentation-only, formatting, comments and small local changes without behavioral or shared-contract impact do not require this audit unless requested. Its unavailability does not block development or replace local checks. Verify agent qa and select only a currently listed, independently confirmed free tool-capable model. The ordered pool is opencode/space-bunny-free (primary, #max only if confirmed), opencode/longcat-2.5-preview-free, opencode/mimo-v2.6-flash-free. Recheck availability, zero pricing and tool_call=true before each audit; skip unverified entries. Prior use is known for the primary; reserves are approved by metadata, not presumed prior use. Never use paid models or silently fall back to the default model.
- On HTTP 429, classify the scope from the actual error before fallback. A model-specific limit permits the next verified free model. An explicit account/provider/shared free-tier quota, billing limit, exhausted credits or shared Retry-After stops all attempts in that scope immediately. FreeUsageLimitError/provider.quota alone with a generic message does not prove scope: permit one reserve probe; if it returns the same ambiguous quota error from that provider, stop conservatively and report scope unknown, possible shared limit. At most three CLI launches total and one launch per model per audit, no same-model retry, polling, automatic resume, paid fallback, or default-model fallback. On success continue the audit on that model; do not launch other reserves. Audit model steps are normal work, not permission to retry quota errors. Stop if internal retrying is observed; do not claim control over undocumented CLI internal retries.
- If all eligible models fail or a shared-limit stop applies, report Independent audit: BLOCKED with actual errors, scope, attempted/skipped models and stop reason. Report SKIPPED only with a concrete below-threshold reason, explicit user opt-out, or a relevant completed audit reused without subsequent substantial changes. Lack of a separate request is not a skip reason for substantial work. Record ordered transitions, exact model IDs/variants, CLI exit codes, session agent/model and actual tool results; a successful model response alone is not a successful audit. Missing tools/evidence or an interrupted audit is BLOCKED or partial, never PASS. Local check results remain separate and development may continue.
- Allow at most two correction-and-recheck cycles for confirmed defects per task. Count each batch of defect fixes followed by validation as one cycle. Reproduce and record evidence before fixing; after two unsuccessful cycles, stop automatic repairs and report remaining failures and limitations. Do not change game logic merely to satisfy a test. Do not weaken tests, suppress errors, install dependencies, or update tools without task authorization.
- Final QA reports state PASS, FAIL, PARTIAL, BLOCKED, or SKIPPED per check, commands and actual results, confirmed reproducible bugs, untested scenarios, and the independent audit status separately. Use SKIPPED for an absent optional lint script, BLOCKED for a required check that could not execute. Passing checks do not prove absence of bugs.
- Before OpenCode QA, Codex selects one small exploration area tied to the latest diff and supplies a brief contract: changed behavior, expected visible result and source, relevant coverage gap, working preview URL, fresh-profile preconditions and available browser capabilities. Codex checks coverage and local-test provenance beforehand; OpenCode must not reread passed test logs, inventory all browser scripts, or traverse the architecture. OpenCode independently chooses concrete UI actions and assertions within that area; Codex must not prescribe the outcome or perform those actions instead. Use docs/qa-exploration.md as the task contract.
- Keep the existing 20-step agent limit. Select a short scenario reachable from a fresh profile, counting navigation/setup as part of the budget; avoid task completion/day transitions or other long paths requiring most of the session just to reach the target. A short branch within the supplied area is sufficient; an unspecified or unreachable area needs clarification, not expansion to the whole game. Publish a brief plan and start UI actions promptly. Reserve remaining steps for result verification, before/after evidence, qa_browser_errors and qa_browser_close; skip optional log/code review first. Do not repeat valid local checks. Read only a pinpoint source fragment if a concrete observation requires clarification.
- If the step budget prevents completing the scenario, result verification, or console-error collection, report Exploration: PARTIAL with executed/unexecuted steps and evidence, never PASS. Missing browser tools, unavailable preview or permission denial preventing the scenario means BLOCKED with the actual error and minimum remedy. Do not expand tools/permissions or switch models to solve either condition. Log-review status stays separate; if intentionally omitted, mark SKIPPED rather than consuming exploration steps.
- Report audit execution, the selected exploratory scenario, and overall application quality separately. Audit PASS is not a claim that the application has no defects. Exploration requested but not executed means combined QA PARTIAL/BLOCKED even if log inspection passed. The same bounded free-model fallback applies to the whole task; tool unavailability is not a reason to cycle through models.
- E2E_TRACE defaults to failure: capture the original scenario with full categories/screenshots, retain its trace only on failure, losslessly compressed as trace.json.gz. E2E_TRACE=all retains successful traces for investigation; off explicitly disables tracing and must be reported. Never rerun a failing scenario just to manufacture a trace. Preserve logs, failure screenshots and errors regardless of retention mode; do not silently discard diagnostic capture failures.

Operational details and environment diagnosis: [docs/qa-workflow.md](docs/qa-workflow.md).

CLI QA browser access is provided by the local v2 plugin in .opencode/plugins/qa-browser; see docs/qa-browser-plugin.md. Prefer its seven qa_browser tools over Desktop attachment or an arbitrary shell adapter. The fixed preview must be running at http://127.0.0.1:4173/voitivaiti/. QA source editing remains denied. For a requested infrastructure smoke make one model attempt only and stop on 429, without invoking reserves just to validate infrastructure; normal audit fallback remains separately authorized.
