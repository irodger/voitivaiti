# Causal routing v0.58.5

Interface and performance now read actual scene outcomes/followups and returned delegation results, rather than rotating scene families by encounter count. Payment keeps its dedicated causal chain. Access/delivery have no cyclic role lens encounters; their separate assignments remain unchanged.

Temporary production result -> delivered recurrence. Verified production result -> delivered review. Review finding without production changes -> artifact work. Unclosed bounded non-production result -> coordination. Returned delegation -> review. Existing explicit incident/contract/environment events select incident/artifact families when attached to the problem; the router does not generate those events.

Ready causal work precedes fresh bound work. Future outcomes are not prematurely delivered. Active tasks reserve their fact. Completed task trigger IDs consume facts across reload. Later proper fixes supersede older consequences. Checked delegation results stop routing.

Context contains source fact, day, previous task/action, actor, outcome and observations. Existing scenes and artifacts remain; their brief uses the real fact key. No UI, career, balance or Company Engine mechanics changed.

Targeted tests cover two non-payment domains, reload, fresh priority, workaround recurrence, review findings and returned colleague work. Legacy review tests wait for actual followups; the long career fixture advances the calendar and makes some bounded decisions rather than relying on automatic family rotation.
