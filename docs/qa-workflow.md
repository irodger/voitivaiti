# Проверки VoitiVaiti

Codex выполняет обязательные проверки самостоятельно. OpenCode используется только для дополнительного независимого аудита по запросу; его недоступность не блокирует разработку. Правила для агентов находятся в корневом AGENTS.md. Это инструкции выполнения QA, а не расписание и не бесконечный процесс автоматических исправлений.

## Порядок

1. Сохранить `git status --short`, проверить `package.json` и diff.
2. Выполнить `npm test`.
3. Выполнить `npm run lint`, только если такой script настроен. Сейчас его нет: линтер не настроен.
4. Выполнить `npm run build`.
5. При изменении E2E или окружения сначала выполнить минимальный сценарий, затем полный набор:

```powershell
node --test --test-concurrency=1 --test-name-pattern="^frontend: onboarding" e2e/professions.e2e.mjs
npm run test:e2e:run
```

Перед полным набором убрать E2E_ROLES и фильтр имён тестов. Полный набор проверяет 22 профессии, полноту матрицы и Escape в словаре. Он включает онбординг, рабочее действие, переключение приложений, восстановление после перезагрузки и мобильную компоновку для выбранных профессий. Это не полное прохождение всех игровых дней.

`npm run test:e2e` объединяет свежую сборку и полный E2E. `test:e2e:run` использует уже существующий dist, поэтому перед ним нужна актуальная сборка. Vite preview поднимается самим тестом на свободном локальном порту; отдельный dev-сервер не нужен.

## Исправленная причина таймаута 2026-10-16

В ограниченной Windows-среде Codex Chromium стартовал и печатал DevTools endpoint, но GPU-процессы завершались с кодом -1073741790 (0xC0000022, ACCESS_DENIED), сетевой процесс также падал. Последнее сообщение: `GPU process isn't usable. Goodbye.` Puppeteer затем выдавал `Timed out after waiting 30000ms` при launch. До загрузки приложения дело не доходило.

Контрольный запуск того же установленного Chrome 155.0.8059.39 вне ограничения занял 365.75 мс и успешно открыл страницу. Исправление — запускать браузерные проверки через разрешённый механизм выполнения вне этой ограниченной среды. Параметры защиты Chromium и таймауты не ослаблены. Зависимости и браузеры при этой работе не устанавливались.

Это ограничение конкретного окружения, а не требование административных прав для всех машин. При повторном отказе нужно запросить разрешённое выполнение или отчитаться о BLOCKED, а не отключать sandbox Chromium.

## Повторное использование и статусы

Успешный полный E2E можно повторно использовать, если после него не менялись поведение игры или тестов, зависимости, конфигурация сборки и браузерное окружение. Изменения документации и форматирования не требуют полного повторного прогона. В отчёте ставится `PASS (reused)` со ссылкой на исходный лог, кодом выхода и объяснением; это не новый запуск. Если происхождение результата или его применимость неясны, нужен повторный прогон.

Отсутствующий необязательный lint script отмечается `SKIPPED`, обязательная проверка, которую выполнить не удалось, — `BLOCKED`. Для OpenCode действуют явные статусы: `SKIPPED — не запрошен` или `BLOCKED — 429; не проведён` (либо другая фактическая причина). Формулировка «не проведён» ниже означает именно BLOCKED при недоступности, а не PASS. Результаты обязательных проверок учитываются отдельно.

Это правила для работы Codex, а не исполняемый контроллер повторов. В проекте нет автоматического адаптера OpenCode, который программно обеспечивает статусы и предел двух исправлений. Его поведение нельзя считать проверенным только на основании документации.

## Диагностика

Тестовый драйвер отдельно отмечает запуск preview, HTTP 200 и готовность Chromium, сохраняет `e2e-artifacts/diagnostics/setup.json`, а при сбое подготовки — `setup-error.txt`. Chromium stderr выводится в консоль; после запуска также записывается в `chromium.log`. Полный вывод команды нужно захватывать с самого начала, чтобы сохранить ошибки самого launch.

Пример сохранения вывода в PowerShell с сохранением кода завершения:

```powershell
New-Item -ItemType Directory -Path 'e2e-artifacts/diagnostics' -Force | Out-Null
npm run test:e2e:run 2>&1 | Tee-Object 'e2e-artifacts/diagnostics/full.log'
$qaExit = $LASTEXITCODE
Set-Content 'e2e-artifacts/diagnostics/full-exit-code.txt' $qaExit
exit $qaExit
```

Для каждой профессии и словаря захватывается полная трасса исходного выполнения с кадрами экрана. По умолчанию `E2E_TRACE=failure`: успешная временная трасса удаляется, трасса упавшего сценария сохраняется без потерь в `trace.json.gz`. `E2E_TRACE=all` сохраняет также успешные трассы для расследования; `off` отключает трассировку и должен быть явно отмечен в отчёте. Для просмотра gzip нужно распаковать в Chrome trace JSON. Повторно запускать ошибку только для записи трассы не нужно. При сбое сжатия исходный временный файл сохраняется, печатается предупреждение.

Замер старого прогона: 23 трассы, 811240147 байт. В исследованной Frontend-трассе основную долю занимают подробные timeline/toplevel-события, скриншоты — около 2.45 МБ. Поэтому кадры и категории не вырезаются: сокращается хранение успешных прогонов, оставшиеся файлы сжимаются. Старые доказательства автоматически не удаляются. Временная запись и CPU-стоимость трассировки остаются; это сокращение постоянного хранения, не обещание нулевой нагрузки.

Скриншоты рабочего шага, `failure.png`, ошибки и логи сохраняются независимо от режима. Если браузер не запустился, скриншот и трасса страницы невозможны — остаются launch/setup-логи. Всё находится в игнорируемом каталоге артефактов.

Проверка готовности preview уже проверяет HTTP-статус: `const response = await fetch(baseUrl, ...)`, затем `assert.equal(response.status, 200, ...)` в `e2e/professions.e2e.mjs`. Сам fetch не бросает ошибку на HTTP 4xx/5xx, но явный assert отклоняет любой финальный статус кроме 200. Это только HTTP-готовность; готовность интерфейса отдельно проверяется браузерными ожиданиями. Редиректы по умолчанию следуются, а тело ответа этим assert не валидируется.

## Исследовательская роль OpenCode QA

Для CLI реализован [ограниченный проектный плагин Puppeteer](qa-browser-plugin.md) с инструментами `qa_browser_*`. Он использует установленный браузер без Desktop подключения и не меняет игровой код. Подтверждение реального управления OpenCode: сеанс `ses_ebe069023ffedP8Ppuyk63OHXS`, agent qa, бесплатная MiMo, семь успешных tool_use, переход «ВОЙТИ» к созданию персонажа, два PNG и явное закрытие браузера. Это инфраструктурный smoke, не завершённый исследовательский аудит игры.

Помимо аудита доказательств агент получает [отдельное исследовательское задание](qa-exploration.md). Он сам изучает поведение и существующее браузерное покрытие, выбирает существенный пробел и пытается проверить его через UI. Чтение логов Codex и повтор существующего smoke не заменяют эту работу. Корректно завершённый аудит и качество игры оцениваются отдельно.

`.opencode/agents/qa.md` разрешает чтение/поиск и browser/execute, сохраняет edit deny и ограниченный shell. Это доступ к инструментам, а не установка интеграции. В OpenCode v2 штатная браузерная группа требует подключения браузера из Desktop ([документация](https://opencode.ai/v2/docs/tools/)). Отсутствие группы или подключения означает `Exploration: BLOCKED` с точной ошибкой и минимальным способом предоставления доступа. Дополнительный свободный shell/Node не предоставляется. Для всей задачи действует прежний fallback и максимум два цикла исправлений.

## Независимый аудит и предел исправлений

OpenCode используется для независимого аудита, которым управляет Codex по этим инструкциям. Отдельного контроллера переключений нет. Стандартные проверки выполняет Codex; аудит не должен повторять их ради расходования квоты. Он может исследовать исходники и подтверждающие артефакты инструментами.

### Подтверждённый пул на 2026-10-16

| Порядок | ID | Основание |
| --- | --- | --- |
| Основная | `opencode/space-bunny-free` | Использовалась ранее; `#max` подтверждён историей сеансов |
| Резерв 1 | `opencode/longcat-2.5-preview-free` | Подтверждена каталогом; без выдуманного варианта |
| Резерв 2 | `opencode/mimo-v2.6-flash-free` | Подтверждена каталогом; без выдуманного варианта |

Все три получены через `C:\Users\raxen\.opencode\bin\opencode.exe models`. Локальный `~/.cache/opencode/models.json` сообщает для каждой `tool_call: true`, `cost.input: 0`, `cost.output: 0`, `cost.cache_read: 0`. [Официальный тариф](https://docs.opencode.ai/docs/zen/) также указывает Free. Метаданные сохранены в `e2e-artifacts/opencode-fallback/model-metadata.json`. Поддержка инструментов по каталогу не означает, что живой вызов уже успешно выполнен. Резервы не выдаются за ранее использованные пользователем модели.

Перед каждым аудитом проверить актуальный список и тариф: бесплатный период может закончиться. Неподтверждённую или отсутствующую модель пропустить с причиной. Не использовать платную модель, имя без `-free` вместо выбранного ID или неявную модель по умолчанию. Не менять глобальные настройки пользователя.

### Ограниченное переключение

1. Запустить `opencode run --agent qa --model <подтверждённый ID> --format json --auto --title <явный заголовок> <задание>` через найденный полный путь CLI. Заголовок задаётся явно; не запускать отдельные запросы генерации заголовка. Сохранить вывод, код завершения, проверить фактические agent/model сеанса.
2. При 429 исследовать тело ошибки и доступные сведения о лимите. При лимите конкретной модели перейти к следующему проверенному резерву.
3. Явный общий лимит аккаунта, провайдера или общего бесплатного тарифа, исчерпанные кредиты, billing cap либо общий Retry-After немедленно прекращает попытки в этом scope. Нельзя пробовать другие модели в том же лимите или обходить его другими аккаунтами.
4. Одна лишь метка `FreeUsageLimitError` / `provider.quota` с сообщением `Rate limit exceeded` не доказывает общий или модельный scope. Допустима одна проба резерва. Если он возвращает тот же неоднозначный отказ от того же провайдера, остановиться консервативно: `BLOCKED — scope неизвестен, возможен общий лимит`. Это предохранитель, а не утверждение о доказанном общем лимите.
5. Максимум три запуска CLI на аудит, один на каждую модель; никаких повторов той же модели, опроса восстановления квоты или бесконечного ожидания. Другие ошибки фиксировать как фактические ошибки, не переименовывать в 429. Не выполнять повтор только для проверки ошибки.
6. При успешном запуске продолжить аудит на выбранной модели; оставшиеся резервы не запускать. Успешный текстовый ответ без инструментов или незавершённое исследование не считать PASS аудита. При наблюдаемых внутренних повторах CLI остановить запуск; инструкции Codex не гарантируют управление недокументированными внутренними повторами.
7. Отчёт содержит статус аудита, итоговую модель, цепочку попыток (ID, вариант, код выхода, ошибка и scope), причину каждого переключения/пропуска, результаты инструментов и ограничения. Если аудит невозможен — `BLOCKED`; если не запрошен — `SKIPPED`; никогда не подменять их PASS. При переключении передать следующей модели уже собранные факты и оставшуюся задачу без повторного выполнения успешных стандартных проверок.

Недоступность всех бесплатных моделей не блокирует разработку. Локальные проверки учитываются отдельно. Этот раздел заменяет прежний запрет любого переключения при 429: теперь разрешён только описанный ограниченный переход между подтверждёнными бесплатными моделями.

На одну задачу допускается не более двух циклов исправления подтверждённых дефектов с повторной проверкой. После двух неуспешных циклов автоматические исправления прекращаются, оставшиеся ошибки передаются в отчёт. Это не разрешение менять игровую логику ради тестов.
