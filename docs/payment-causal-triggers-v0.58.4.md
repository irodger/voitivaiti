# Payment: причинные поводы, v0.58.4

Оплата получает следующую рабочую ситуацию только из необработанного факта мира. Счётчики сценариев и число прошлых встреч не выбирают её продолжение. Остальные домены и их выбор не изменены.

## Связный пример

1. Игрок проверяет ограниченный локальный обход и передаёт результат. В мире сохраняются ограничение и отложенная проверка QA, связанная с конкретным действием.
2. Пока QA не закончила проверку, новая задача оплаты не появляется. В рабочий день отчёт становится отдельным поводом: идентификатор, исходное решение, коллега, день и причина.
3. История сообщает, почему вернулись к оплате сейчас, но не раскрывает техническую причину. Игрок изучает прежний результат и запрашивает Backend.
4. Ответ Backend меняет доступные действия: вместо догадки только о кнопке доступны сравнение контракта и воспроизведения QA. Открытые данные сохраняются после reload.
5. Проверенный proper fix закрывает ограничение и потребляет повод. Само завершение не создаёт очередной сбой. Следующий герой получает проверенный результат прежнего героя через существующую цепочку передачи.

Review и согласованное изменение контракта имеют собственные источники. Более существенный новый факт может заменить ещё не взятый повод; его идентификатор сохраняется отдельно. Во время активной задачи новые факты остаются в очереди, чтобы не переписывать её артефакты.

## Сохранения и проверка

Сохраняются ожидающие события, готовый повод, обработанные и заменённые идентификаторы. Старая фаза сама по себе не считается новым фактом: миграция принимает только доставленный и ещё не отработанный отчёт.

Targeted tests проверяют задержку отчёта QA, независимость от 120 косметических встреч, источник события, смену действий после ответа Backend, отсутствие автоматического возврата после proper fix, отдельный контрактный повод и reload на разных этапах. Старые тестовые сценарии карьеры теперь ожидают реальный отчёт вместо немедленного повторения оплаты; правила карьеры не менялись.
